1. Project Overview & Objectives

In contemporary retail and supply chain operations, accurate tracking of stock, reliable supplier information, and comprehensive audit trails of goods movement are critical. Project Statement 2: Inventory Management System provides an enterprise-ready database and application design engineered to handle warehouse logistics, real-time stock deductions, restock shipments, and defective returns.

1.1 Core Objectives

  • Supplier Relationship Management: Centralize complete contact, geographic, and communication credentials for all vendor organizations.
  • Product Catalog Standardization: Maintain comprehensive SKU records with detailed descriptions, supplier linkage, unit pricing, and real-time inventory counts.
  • Transactional Movement Auditing: Record every inflow and outflow using strongly typed movement classifications (Purchase, Sale, Return) with timestamps and order notes.
  • Automated Business Intelligence: Deliver instant SQL metrics for low-stock thresholds, inventory asset valuation, and supplier fulfillment performance.
  • Interactive Cloud Accessibility: Eliminate static spreadsheets by integrating the database into a secure, responsive web portal hosted in the cloud.

The system follows Third Normal Form (3NF) relational principles to eliminate data redundancy while maintaining relational integrity via Foreign Key cascade rules.

4. SQL Implementation (DDL & Seed Data)

4.1 Complete Schema Creation Script

-- Drop existing tables in reverse dependency order
SET FOREIGN_KEY_CHECKS = 0;
DROP TABLE IF EXISTS InventoryTransaction; DROP TABLE IF EXISTS Product; DROP TABLE IF EXISTS Supplier;
SET FOREIGN_KEY_CHECKS = 1;

CREATE TABLE Supplier (
    SupplierID   INT          PRIMARY KEY AUTO_INCREMENT,
    SupplierName VARCHAR(150) NOT NULL,
    ContactName  VARCHAR(100), ContactTitle VARCHAR(100),
    Address      VARCHAR(200), City VARCHAR(100), Region VARCHAR(100),
    PostalCode   VARCHAR(20),  Country VARCHAR(100), Phone VARCHAR(30), Email VARCHAR(150)
);

CREATE TABLE Product (
    ProductID       INT            PRIMARY KEY AUTO_INCREMENT,
    ProductName     VARCHAR(150)   NOT NULL,
    Description     TEXT,
    SupplierID      INT,
    UnitPrice       DECIMAL(10,2)  NOT NULL DEFAULT 0.00,
    QuantityInStock INT            NOT NULL DEFAULT 0,
    CONSTRAINT fk_product_supplier FOREIGN KEY (SupplierID) REFERENCES Supplier(SupplierID)
        ON UPDATE CASCADE ON DELETE SET NULL
);

CREATE TABLE InventoryTransaction (
    TransactionID   INT  PRIMARY KEY AUTO_INCREMENT,
    ProductID       INT  NOT NULL,
    TransactionType ENUM('Purchase', 'Sale', 'Return') NOT NULL,
    Quantity        INT  NOT NULL,
    TransactionDate DATE NOT NULL,
    Notes           TEXT,
    CONSTRAINT fk_transaction_product FOREIGN KEY (ProductID) REFERENCES Product(ProductID)
        ON UPDATE CASCADE ON DELETE CASCADE
);

5.2 Stock Movement Summary (Purchased vs. Sold vs. Returned)

SELECT p.ProductName,
    COALESCE(SUM(CASE WHEN t.TransactionType = 'Purchase' THEN t.Quantity ELSE 0 END), 0) AS TotalPurchased,
    COALESCE(SUM(CASE WHEN t.TransactionType = 'Sale'     THEN t.Quantity ELSE 0 END), 0) AS TotalSold,
    COALESCE(SUM(CASE WHEN t.TransactionType = 'Return'   THEN t.Quantity ELSE 0 END), 0) AS TotalReturned,
    p.QuantityInStock AS CurrentStock
FROM Product p LEFT JOIN InventoryTransaction t ON p.ProductID = t.ProductID
GROUP BY p.ProductID, p.ProductName, p.QuantityInStock ORDER BY p.ProductName;

6. Web Dashboard & Cloud Deployment

To eliminate spreadsheet fragmentation, a live reactive web dashboard was constructed with Python Flask and hosted serverless on Vercel, directly interfacing with the Aiven Cloud MySQL database over verified SSL/TLS.

Production Web Portal: https://inventorymanagement-lake.vercel.app

6.1 Full CRUD Architecture

  • Create (POST): Modal dialogues allow adding new products (with supplier binding), vendors, and transactions without manual SQL queries.
  • Read (GET): Live reactive tabular feeds showing real-time stock balances, supplier contacts, and transaction logs.
  • Update (PUT & PATCH):
    • Full Modal Edit: Allows updating pricing, descriptions, and supplier assignments.
    • Quick-Stock Stepper: Inline [-] and [+] incrementers allowing warehouse workers to adjust unit counts in a single click.
  • Delete (DELETE): Double-confirmation modal alerts preventing accidental permanent removals.

6.2 Security & Integrity Features

  • SSL/TLS Certificate Authority Verification: All connections between Vercel Serverless Functions and Aiven MySQL are encrypted using an embedded ca.pem certificate, guaranteeing zero plaintext transit.
  • SQL Injection Prevention: All API queries utilize parameterized prepared statements (%s placeholders via mysql.connector).
  • Cross-Site Scripting (XSS) Sanitization: Input strings are sanitized via utility escaping functions before rendering in the DOM.
